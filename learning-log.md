# Learning Log

## Week 1

This week I worked on the Python Foundations practical project. I learned and practiced Python development, Git, GitHub, debugging, code quality, and environment configuration.

### Python

- Worked with Python 3.12 and VS Code.
- Learned how to use list, dictionary, and nested comprehensions.
- Refactored old scripts using dataclasses.
- Used pathlib for working with files and paths.
- Used context managers when working with files.
- Created custom exception classes to handle invalid user input.
- Added full type hints and checked the project using Mypy in strict mode.

### CLI Development

- Built a command-line tool that reads data from a CSV file.
- Learned how to clean and filter CSV data.
- Added validation for user input and CSV columns.
- Learned how to print a summary table from the processed data.

### Code Quality

- Learned how to use Ruff for linting.
- Learned how to use Black for code formatting.
- Learned how to use Mypy for static type checking.
- Combined the quality checks so they can be run with one command.

### Debugging

- Learned how to use the VS Code debugger.
- Practiced breakpoints, step over, step into, and watching variables.
- Debugged a problem without using `print()` statements.

### Git and GitHub

- Learned how to create and work with feature branches.
- Practiced `git stash`, `git reset --soft`, and `git revert`.
- Learned how to fix an incorrect commit message using `git commit --amend`.
- Created Pull Requests and reviewed my own changes before merging.
- Learned how to keep a clean Git history while working on different tasks.

### Environment Configuration

- Learned how to use `.env` files for environment variables.
- Used `python-dotenv` to read configuration from `.env`.
- Learned why `.env` should not be committed to GitHub.
- Created `.env.example` as a safe template for the required variables.

### Reflection

The biggest improvement this week was learning how to combine Python development with a proper Git and GitHub workflow. I also learned that writing clean, typed, and maintainable code is as important as making the code work.
